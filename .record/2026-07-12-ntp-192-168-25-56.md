# 2026-07-12 NTP 漂移机器事故登记（192.168.25.56）

## ⚠️ 重要：本文件**仅作事故登记**

按 `AGENTS.md` 时钟管理硬规则（任务 0）：

> **禁止 NTP 校时**：edge 端和 ongrid 服务端的系统时钟不允许通过任何代码路径 / 配置文件 / 部署脚本 / 运维手册修改（包括但不限于 NTP sync、chrony、systemd-timesyncd、`timedatectl set-time`、`date -s`、sntp、w32tm 等）。

下面登记的 192.168.25.56 时钟漂移问题**不在本仓库 / 镜像 / 配置中做任何修复**，仅作为运维事故信息存档。

---

## 漂移现象

| 机器 | 角色 | 时钟状态 | 观察时间 |
|---|---|---|---|
| 192.168.25.56 | edge | CLOCK_REALTIME 漂移 forward ~22min | 2026-07-12 |

## 现象影响

| 系统组件 | 现象 | 修复方案 |
|---|---|---|
| edge metrics scrape | Scrape 时间戳（TsMs = `time.Now()`）落到未来 22min；Prom `remote_write` 拒收样本 | v3.3 方案：tunnel.PromSample.ServerTimeMs 字段 + manager ingester 用 ongrid 时间作 Prom sample.timestamp（详见 `.record/2026-07-12-metrics-timestamp-server-time-anchored.md` 任务 4） |
| edge journald → Loki | `entry.timestamp` 落在未来 22min；Loki `creation_grace_period: 30m` 余量薄 | v3.3 方案：`creation_grace_period` 30m → 720h(30d)（详见同上文件任务 5）|

## 根因

- systemd-timesyncd 未成功同步（边缘机器可能没有正确配置 NTP 上游、或根本没装 NTP）
- 192.168.25.56 已运行较久（硬件时钟 / 软件时钟漂移累积），root cause 是"系统长时间没同步"

## 不做的修复

| 操作 | 不做原因 |
|---|---|
| `chronyd` / `systemd-timesyncd` 同步到 manager | AGENTS.md 时钟管理硬规则禁止 |
| `timedatectl set-time` / `date -s` 调时间 | 同上 |
| `hwclock --systohc` 写硬件时钟 | 同上 |
| 改 `/etc/chrony.conf` 加 `server 192.168.25.30 iburst` | 同上 |
| firewalld 开放 ntp 端口 | 同上 |

## 替代方案（已实施）

| 关注点 | 替代方案 | 落地位置 |
|---|---|---|
| Prom 接收样本不被拒收 | edge 端不透传本地时间作为 Prom sample.timestamp，而是用 ongrid 服务端时间 | `internal/edgeagent/biz/agent.go` + `internal/pkg/tunnel/messages.go` + `internal/manager/biz/promwrite/ingester.go` |
| Loki 接收日志不被拒收 | 放宽 Loki 服务端 grace period | `deploy/install/loki-config.yaml` |

两个机制都不涉及修改 edge 系统时钟 — 都是"数据时间戳 + 服务端配置兜底"的设计（不是治本，治本依赖 NTP，按 AGENTS.md 硬规则不做）。

## 后续运维观察点

1. **Prom `out of bounds` 日志计数** — 应在 v3.3 上线后逐步降为 0
2. **Loki `timestamp too new` 日志计数** — 应在 v3.3 上线后逐步降为 0
3. **edge 日志 `edge_ts_ms` label vs Prom sample.timestamp 差值** — 即可推断 192.168.25.56 真实漂移量
4. **本次 v3.3 方案适用所有未来漂移机器** — 即使 192.168.25.56 漂移到 30 天以上，Loki grace 也兜得住；Prom 路径完全不依赖 edge 时钟

## 不在 .record 内做修复的明确边界

- 不修改 `/etc/chrony.conf` / `/etc/ntp.conf` / `/etc/systemd/timesyncd.conf`
- 不修改任何部署脚本里的 `chronyd` / `timedatectl` / `hwclock` 调用
- 不在 installer / upgrade.sh 里加 NTP 校时步骤
- 不在运维 runbook 里写"通过 NTP 校时修复 192.168.25.56 漂移"
