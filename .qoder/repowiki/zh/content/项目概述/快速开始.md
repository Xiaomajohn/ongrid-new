## 简介
本指南面向新用户，帮助你在 30 分钟内完成 OnGrid 的部署并体验核心功能。OnGrid 提供“云端管理器 + 边缘节点”的架构：在目标主机上运行管理器，通过反向隧道连接受管设备；无需在设备上开放入站端口，即可实现监控、日志、链路追踪、告警与远程执行等能力。

## 前置环境要求
- 操作系统：Ubuntu 22.04+、Debian 12+、RHEL/Rocky 9（amd64 / arm64）
- Docker：>= 24.0，且支持 docker compose v2（子命令为 `docker compose`）
- 资源建议：至少 2 GB 内存、10 GB 可用磁盘
- 权限：以 root 或具备 sudo 权限的用户执行安装脚本
- 网络：可访问 docker.io（用于拉取 MySQL、Prometheus 等镜像；ongrid 镜像已打包在发布包内）

## 一键安装（推荐）
以下命令适用于 AMD64 与 ARM64 两种架构。请根据服务器 CPU 选择对应版本。

- AMD64
```bash
wget https://github.com/ongridio/ongrid/releases/download/v0.9.0/ongrid-v0.9.0-linux-amd64.tar.xz
tar -xf ongrid-v0.9.0-linux-amd64.tar.xz && cd ongrid-v0.9.0-linux-amd64
sudo ./install.sh
```

- ARM64
```bash
wget https://github.com/ongridio/ongrid/releases/download/v0.9.0/ongrid-v0.9.0-linux-arm64.tar.xz
tar -xf ongrid-v0.9.0-linux-arm64.tar.xz && cd ongrid-v0.9.0-linux-arm64
sudo ./install.sh
```

说明
- 安装完成后，Web UI 默认通过 HTTPS 暴露（端口可在 .env 中调整）。
- 安装脚本会自动检测并生成自签证书；生产环境建议替换为正式证书。
- 安装脚本会打印 Web URL 与管理员初始密码，便于首次登录。

## 分步安装与配置选项
如果你需要更细粒度的控制，可按以下步骤进行。

### 步骤 1：准备安装包
- 将对应架构的 tar.xz 上传到目标主机并解压
- 进入解压后的目录

### 步骤 2：可选编辑 .env
- 复制模板为 .env：`cp deploy/install/.env.example .env`
- 按需修改端口、管理员账号密码、OpenAI 密钥等关键项
- 若留空，部分密钥会在首次启动时自动生成

### 步骤 3：执行安装
- 运行 `sudo ./install.sh`
- 安装脚本会：
  - 自检 Docker 环境，必要时自动安装 Docker 与 compose v2
  - 创建统一安装目录（默认 /opt/ongrid），拷贝 compose 与配置文件
  - 生成自签 TLS 证书（如未提供）
  - 拉起服务并轮询健康检查
  - 输出 Web URL、API URL 与管理员初始密码

### 步骤 4：验证安装
- 浏览器访问 `https://<host>:<HTTP_PORT>/`（默认 443）
- 使用 .env 中的管理员邮箱与密码登录

### 安装脚本参数
- --mode <compose|systemd>：选择容器模式（默认）或 systemd 原生模式
- --profile monitoring：兼容旧版保留参数（当前 Prometheus 为核心服务，始终启动）
- --no-seed：跳过管理员工具提示
- --force：在已有安装基础上重装（保留 .env 与数据卷）
- --with-deps：仅 systemd 模式有效，自动安装依赖组件

## Docker Compose 开发环境搭建
适合本地开发与调试，非生产用途。

- 准备环境变量
  - 复制示例：`cp deploy/.env.example .env`（如需）
  - 按需修改管理员账号、数据库密码等
- 启动服务
  - `make compose-up` 或 `docker compose -f deploy/docker-compose.yml up -d`
- 停止服务
  - `make compose-down` 或 `docker compose -f deploy/docker-compose.yml down`

注意
- 该 compose 栈包含 mysql、ongrid、frontier、nginx、prometheus、grafana 等
- 默认不对外暴露 HTTP API 与 Edge 隧道端口（仅 metrics 暴露 9100）
- 如需 SQLite 本地模式，参考 deploy/README.md 的切换说明

## 首次使用流程
- 登录 Web 界面
  - 打开 `https://<host>:<HTTP_PORT>/`，使用 .env 中的管理员邮箱与密码登录
- 添加设备（Edge）
  - 在管理器中创建 Edge 节点，获取 access_key 与 secret_key
  - 在目标主机上执行 edge 安装脚本，传入云端地址与凭据
- 查看监控数据
  - 通过内置 Grafana 面板查看服务器详情、CPU/内存/Load/网络等指标
  - 也可通过 Prometheus 接口直接查询
- 执行运维任务
  - 使用内置工具与技能（如重启服务、探测连通性、读取日志等）
  - 所有操作均审计并可回放

## 常见问题排查
- 端口冲突
  - 现象：`bind: address already in use`
  - 处理：编辑 .env 中的 `ONGRID_HTTP_PORT`、`ONGRID_HTTP_REDIRECT_PORT`、`ONGRID_TUNNEL_PORT`、`ONGRID_METRICS_PORT`，然后重起服务
- host-gateway 不支持
  - 现象：`invalid IP address in add-host: "host-gateway"`
  - 处理：安装脚本会自动写入 `ONGRID_HOST_GATEWAY=<docker0 网关>`；如仍失败，手动设置后重起
- MySQL healthcheck 超时
  - 现象：MySQL 冷启动慢导致健康检查失败
  - 处理：观察 `docker logs ongrid-mysql`，等待其进入 healthy；安装脚本会轮询健康状态
- /healthz 不通
  - 现象：管理器无法返回健康状态
  - 处理：检查 `.env` 中的 `ONGRID_JWT_SECRET` 是否为空、`ONGRID_DB_DSN` 是否正确
- AI Chat 接口 500
  - 现象：调用聊天接口返回 500
  - 处理：填写 `OPENAI_API_KEY` 或不调用聊天接口
- Edge 连不上
  - 现象：边缘节点无法连接云端
  - 处理：检查云端 `ONGRID_TUNNEL_PORT`（默认 40012）防火墙；在边缘主机查看 `journalctl -u ongrid-edge -n 100`

## 中国地区镜像源配置
- 下载包镜像
  - 如果 GitHub 下载较慢，可使用国内 CDN 镜像下载对应架构的安装包
    - AMD64：`https://ongrid.cloud/dl/ongrid-v0.9.0-linux-amd64.tar.xz`
    - ARM64：`https://ongrid.cloud/dl/ongrid-v0.9.0-linux-arm64.tar.xz`
- Docker Hub 镜像加速
  - 安装脚本会探测 Docker Hub 可达性；不可达时自动写入 `/etc/docker/daemon.json` 的 registry-mirrors 列表，并重启 docker
  - 若你已自定义镜像源，脚本不会覆盖现有配置
