## 架构概览

Ongrid 采用「启动时环境变量 + 运行期系统设置」双层配置模型，由共享的 internal/pkg/config 包统一加载，供云端 ongrid 与边缘 ongrid-edge 两个二进制复用。

- 启动层（静态）：所有以 ONGRID_* 为前缀的环境变量通过 config.Load() 解析为强类型结构体，提供合理的 Go-side 默认值；该阶段不依赖任何外部服务或文件系统。
- 运行期层（动态）：部分敏感/易变参数（LLM API Key、Prom/Grafana/Loki/Tempo URL、WebSearch Provider 等）在首次启动时从 env 种子写入 system_settings 表，随后通过 UI 编辑持久化，并由 Resolver 带 TTL 缓存按需读取，无需重启生效。

## 核心文件与职责

- internal/pkg/config/config.go：唯一配置入口，定义 Config 树形结构体，实现 Load() 从 os.Getenv 解析并应用默认值，提供 getEnvBool/getEnvInt/getEnvFloat/getEnvDuration/getEnvCSV/splitProviderModels 等解析器
- cmd/ongrid/main.go：云端主进程调用 config.Load()，并在启动流程中把 env 值作为首次启动种子写入 system_settings（LLM/Prom/Grafana/Loki/Tempo/WebSearch），后续由 UI 覆盖
- cmd/ongrid-edge/main.go：边缘 Agent 同样调用 config.Load()，仅消费 Edge.* 子段（CloudAddr/AccessKey/SecretKey/CollectorMode/ScrapeConfigFile/CollectorInterval）
- deploy/install/.env.example：生产安装模板，集中列出所有 ONGRID_* 变量及含义，install.sh 会将其渲染到容器 .env / systemd EnvironmentFile
- deploy/install/edge/ongrid-edge.env.example：边缘节点专用 env 模板，install-edge.sh 渲染后写入 /etc/ongrid-edge/ongrid-edge.env，被 systemd 的 EnvironmentFile= 注入进程环境
- internal/pkg/config/config_test.go：断言所有默认值与覆盖路径，是新增配置项的回归基线

## 设计约定与分层

1. 命名规范：所有可配置项均以 ONGRID_ 为前缀，按功能域分组（如 ONGRID_DB_*、ONGRID_PROM_*、ONGRID_EDGE_*、ONGRID_NOTIFY_*、ONGRID_ALERT_*）。
2. 类型安全解析：禁止在业务代码里直接 os.Getenv 再自行转换；统一走 config.Load() 返回的强类型结构体，避免字符串误用。
3. 默认值优先：每个字段都有 Go-side 合理默认值（如 HTTPAddr=:8080、DB Dialect=mysql、Edge CollectorMode=off），保证零配置也能拉起最小可用栈。
4. 敏感信息种子策略：对需要持久化的密钥类配置（OpenAI/Anthropic/Zhipu/Gemini/DeepSeek/Kimi API Key、Prom QueryURL/RemoteWriteURL、Grafana RootURL、Loki/Tempo URL、WebSearch Provider/URL），main 启动时执行 settingSvc.SetIfAbsent(...) 只写一次，后续 UI 编辑永久覆盖。
5. 运行时热更新：LLM 多提供商路由使用 LLMSettingsResolver，每 60s 刷新 DB 中的 system_settings.llm.* 行，UI 保存后 chat 面可在约 60s 内感知变更，无需重启。
6. 边缘侧独立配置域：EdgeConfig 专供 ongrid-edge，包含连接云端的 CloudAddr/AccessKey/SecretKey 以及采集模式（off/auto/embedded/scrape）、scrape.yaml 路径、插件 bin/work 目录等，与云端配置互不影响。
7. 向后兼容：部分 main 中仍直接 os.Getenv 的开关（如 ONGRID_OTEL_ENDPOINT、ONGRID_AUDIT_RETENTION_DAYS、ONGRID_EMBEDDING_PROVIDER/MODEL/DIM、ONGRID_INVESTIGATOR_*、ONGRID_DEFAULT_LOCALE、ONGRID_MARKETPLACE_DEVMODE）属于过渡态，未来应迁移至 config.Config 统一管理。

## 开发者规则

- 新增配置项：在 internal/pkg/config/config.go 的对应 struct 字段上添加注释说明 env 名与默认值，在 Load() 中完成解析，在 config_test.go 中补充默认值与覆盖用例。
- 敏感配置持久化：若需 UI 可编辑且重启保留，遵循 main 中 SetIfAbsent 模式：启动时从 env 种子写入 system_settings，业务层通过 Resolver 读取。
- 避免散落的 os.Getenv：除极少数过渡开关外，所有配置必须经 config.Load() 暴露，禁止在 handler/biz 层直接读环境变量。
- 边缘配置隔离：on-grid-edge 专属参数放在 EdgeConfig 下，不要混入云端配置结构体。
- 部署模板同步：新增 ONGRID_* 变量后，务必在 deploy/install/.env.example 与 deploy/install/edge/ongrid-edge.env.example 中添加条目与注释，保持文档与代码一致。

## 置信度

high — 存在单一权威配置加载包 internal/pkg/config，两个二进制均复用同一套 Load()，并有完整测试覆盖默认值与覆盖路径；同时配套 install 模板与运行期 system_settings 种子机制，形成清晰的 env -> 结构体 -> 可选持久化三层体系。
