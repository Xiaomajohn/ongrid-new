采用清晰的四层依赖方向：`server/`（HTTP 路由与鉴权中间件）→ `service/`（BC 聚合门面，组合 user/org/membership/authz）→ `biz/*/`（用例与仓储接口）→ `data/*/store`（GORM 持久化实现），`model/` 作为跨层共享实体。

- `model/model.go` 定义三张表实体 `User` / `Org` / `OrgMembership` 及系统角色常量，是唯一的持久化契约。
- `biz/user` 通过 `Repo` 接口解耦存储；`biz/org`、`biz/membership` 各自暴露 `Service` 结构体供上层组装。
- `biz/authz` 封装 casbin（gorm-adapter 持久化到 `casbin_rule`），维护硬编码的 role→obj:act 矩阵并通过 `SyncMembership` 把 `OrgMembership` 镜像为 g 规则；`Enforcer.AllowAnyOrg` 支持无 X-Active-Org 时的默认域回退。
- `service.Service` 是 HTTP 层唯一入口，org/membership/authz 字段可 nil，未接入时返回 503，保证旧部署平滑升级。
- `server/http.go` 使用 chi v5 注册 `/v1/auth` 与 `/v1/users`、`/v1/orgs` 路由，内置进程内登录速率限制（IP+Email 双窗口）并调用 manager 层的审计中间件记录操作日志。
- 密码使用 argon2id 哈希（`biz/user/hash.go`），JWT 由 `internal/pkg/auth.Signer` 签发，access/refresh 双令牌。
