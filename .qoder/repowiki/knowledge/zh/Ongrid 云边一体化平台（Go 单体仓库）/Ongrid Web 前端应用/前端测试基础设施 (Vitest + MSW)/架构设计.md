模块围绕 Vitest 单入口组织：
- `web/vitest.config.ts` 通过 `mergeConfig(viteConfig, ...)` 复用 Vite 的 `@/` 别名与 React 插件，并在 `test` 块中声明全局 API、jsdom 环境、CSS 关闭以及 `setupFiles: ['./src/test/setup.ts']`。
- `src/test/setup.ts` 是测试生命周期钩子的唯一注册点：引入 `@testing-library/jest-dom` 断言扩展；在 Node 22+ 实验性 `localStorage` 覆盖 jsdom 时注入内存 Storage 实现；使用 `beforeAll/afterEach/afterAll` 启动 MSW server（`onUnhandledRequest: 'error'`）、每个用例后重置 handler、结束后关闭服务。
- `src/test/msw-server.ts` 仅暴露一个空的 `setupServer()` 实例，约定各 `*.test.tsx` 通过 `server.use(...)` 在文件级注册请求拦截，保证 fixture 与断言一一对应。
- `src/test/fixtures/marketplace.ts` 按 wire shape (`@/api/marketplace`) 导出 `CapabilityDeclaration` / `InstalledPack` / `RegistryEntry[]` 等常量，作为 UI 测试的数据源。
依赖方向单向：fixtures → setup → msw-server → vitest.config；测试文件只消费这些导出，不反向依赖业务代码。
