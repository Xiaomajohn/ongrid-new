模块按三层划分：
- `server/secret`（HTTP 层）：基于 chi 注册 `/v1/secrets` CRUD 与 `/v1/credential-types` 列表路由，所有接口强制 admin 鉴权，响应统一经 `writeErr`/`errCode`/`errSlug` 映射到标准错误码。
- `biz/secret`（业务层）：`Usecase` 封装凭据的加密封装（`seal`/`unseal` 调用 `internal/pkg/secretbox`）、字段清洗（`clean`）、红视图转换（`toView` 仅输出字段名），并提供 `ResolveFields` 与 `ResolveInjection` 两条进程内解密路径；通过 `Repo` 接口与数据层解耦。
- `data/secret/store`（持久化层）：GORM-backed `Repo` 实现，仅存取已密封的 Data 字符串，不感知明文；`migrate.go` 通过 `AutoMigrate(&model.Secret{})` 建表。

依赖方向严格单向：`server → biz → data`，`biz` 反向依赖 `internal/pkg/credinject` 完成 n8n 风格的模板注入解析。`credtype.go` 在 init 中注册内置类型（custom/tencentcloud/aws/alicloud/github），通过 `LookupCredType` 回退到 custom，使未声明类型的凭据仍可注入。
