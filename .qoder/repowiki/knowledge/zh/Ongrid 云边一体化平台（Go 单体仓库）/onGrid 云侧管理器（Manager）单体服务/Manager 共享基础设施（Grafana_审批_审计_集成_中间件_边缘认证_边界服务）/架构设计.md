本模块按职责切分为六个并列子包，均遵循「薄 HTTP 层 → 窄接口 → biz/service」的依赖方向，不互相直接 import 具体实现，而是通过接口解耦：
- `biz/grafana`：编排 Grafana 自动配置（SA+Token 引导、Prometheus datasource upsert、嵌入 dashboard JSON 推送），依赖 `settingbiz.Service` 读取 system_settings，调用 `pkg/grafana.Client`；dashboard JSON 通过 `//go:embed dashboards/*.json` 编译进二进制。
- `biz/approval` + `biz/audit`：纯 usecase 层，分别暴露 `Repo`/`Executor` 和 `Repo` 接口，由 data 层实现，producer 通过 `RegisterExecutor` 注册执行器，审计写入失败仅 warn 不阻塞业务。
- `server/integration`：chi 路由薄壳，定义 `GrafanaService`/`URLProbe`/`PromQuerier` 等窄接口，把 `/v1/integrations/*` 请求委派给对应 biz 服务，统一错误映射到 `{error, code}` JSON。
- `server/middleware`：两个独立 chi 中间件——`AuditMiddleware` 在 ctx 中注入可变的 `*auditSlot`，由 handler 显式 `SetAuditEvent` 标注才落盘；`MetricsMiddleware` 基于 `chi.RoutePattern` 记录 ADR-026 自观测指标，404 归入 route="unknown" 控制基数。
- `server/edgeauth`：供 nginx `auth_request` 调用的内部端点 `/internal/auth/dataplane-verify`，复用 edge 访问密钥认证逻辑，返回 `X-Edge-Id` 供下游注入标签。
- `service/frontierbound`：manager 侧对上游 `singchia/frontier` geminio 服务的封装，维护 transportID↔edgeID 双向映射，安装 register_edge / heartbeat / push_host_metrics / push_prom_samples / get_plugin_configs / shell_output / shell_exit 等反向 RPC 处理器，并通过 `Wiring` 结构体以可选接口（`PromIngester`、`WebshellRouter`、`PluginConfigFetcher`）接入上层 biz。
- `service/aiopsconfig`：将 `manager/service/alert` 的 `PreviewRule/CreateRule` 适配为 `biz/aiops/tools.ConfigManager` 所需的 `alertRulePort`，作为 AI Ops 工具链的配置后端桥接层。

依赖方向严格单向：`server/*` → `biz/*` → `data/*`；`service/*` 面向 biz 层暴露 client/handler，不被 server 直接依赖。所有外部依赖（DB、geminio、Grafana API、PromQL）均以接口或函数适配器形式注入，便于 e2e 禁用与 mock。
