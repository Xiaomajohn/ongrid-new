模块按 `biz` / `server` / `provider` 三层切分：
- `server/imbridge/http.go` 基于 chi 注册两类路由：公开入口 `/v1/im/{provider}/events`（由平台签名校验鉴权）与管理端 CRUD `/v1/im/apps`（requireAdmin 守卫），负责反序列化平台信封、解密/验签、提取 `InboundMessage` 后异步调用 `biz.Bridge.HandleInbound`。
- `biz/imbridge` 是纯业务层：`Bridge` 通过 `Repo`（ImApp/Thread 映射）、`AgentSession`（aiops 的 `PostMessageStreamWithOpts` 抽象）和 `Sender`（平台发送器）三个接口组合，完成会话解析、`/new` 重置、占位消息 + 流式编辑器（`stream_supervisor.go` 中的 `streamEditor`）以及去重（`dedup.go` 基于内存 set）。`usecase.go` 暴露 `UC` 供 HTTP 管理端做 ImApp 的增删改查与字段校验（mode/stream|webhook、default_locale=en|zh、Telegram/Slack 强制 allow_from 白名单）。
- `provider/{feishu,telegram,slack}` 各自提供 `Client`（HTTP OpenAPI 客户端，含 token 缓存）与 `stream.go`（长轮询/Socket Mode 拉取），并通过 `adapter.go` 中统一的 `Adapter` 接口被上层复用；每个 provider 还实现 `Sender` 以支持回写消息。
依赖方向单向：`server → biz → provider`，biz 对 aiops 与数据层均通过接口解耦，便于测试注入 fake。
