模块按分层拆分为四层：
- `server/metric`：HTTP 路由层（go-chi），`http.go` 提供 `/v1/edges/{id}/metrics` 的 legacy MySQL 兼容路径，`prom_handler.go` 是 Prometheus 后端实现，二者共享同一 `pointDTO`/`queryResp` 响应结构并通过 `MetricService` 窄接口解耦；同时暴露 `/v1/metrics/query_range` 作为鉴权后的 PromQL 透传。
- `biz/metric`：领域业务层，定义 `Writer`/`Reader` 存储无关接口（`repo.go`）以及 `Ingester`（带 drop-oldest 缓冲、指数退避重试 + dead-letter 落盘）、`Downsample`（raw→5m→1h 两阶段聚合）、`Retention`（按表循环删除）。所有持久化通过 `internal/manager/model/metric` 的纯 Go 模型类型传递，不感知 GORM/ClickHouse。
- `data/metric/store`：GORM 实现层，`writer.go`/`reader.go` 以 `createInBatches(500)` 批量写入并复用 `deleteBefore` 子查询模板做三表保留期删除；`provider.go` 仅暴露 `NewBizWriter/NewBizReader` 供 cmd 组装，避免把具体 Writer 类型泄露到 wiring 层。
- `biz/promwrite`：Prometheus remote_write 桥接层，负责给每样本注入 `device_id`/`ongrid_source` 标签、排序 label 集、统计连续失败次数并通过 `HealthSnapshot()` 暴露给告警评估器。
依赖方向严格单向：`server → biz → data/store`，`promwrite` 独立依赖 `internal/pkg/promwrite` 和 `internal/pkg/tunnel`，不反向依赖 manager 其他子域。
