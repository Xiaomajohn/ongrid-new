本模块由四个独立子包组成，均位于 `internal/manager/biz/aiops/` 下，通过窄接口与上层 service 层解耦：
- `agent`：实现 OpenAI function/tool-calling 主循环（`Run`/`RunStream`），按 `MaxIterations` 轮次调用 `llm.Client.Chat`，将 assistant 与 tool 消息持久化到 `biz.SessionRepo`，并通过 `Emit` 回调向 SSE 推送 `assistant`/`tool_start`/`tool_end`/`done` 等事件；依赖 `tools.Registry` 执行工具、`mentions.MentionResolver` 内联 @ 引用、`toolreplay.Resolve` 重建 tool_calls。
- `investigator`：在告警首次触发时异步拉取 `correlate_incident` 工具结果并单轮调 LLM 生成初查报告，写入 `alert.EventWriter.CreateEvent`；内部用固定大小 channel + goroutine pool 做背压，队列满则丢弃而非阻塞告警路径。
- `mentions`：只读搜索门面，聚合 device/alert/logquery 三个下游 usecase，返回 `Item` 列表供 SPA 弹出框展示，并提供 `Resolve` 把结构化引用转成 markdown bullet 注入 agent 上下文。
- `toolreplay`：纯函数库，从 `chat_messages`+`chat_tool_calls` 历史中恢复 LLM 分配的 `tool_call_id`（优先 `LLMCallID`，回退按顺序配对 role=tool 行），并支持按 call_id 重排以应对并行工具导致的乱序。

依赖方向单向向外：`agent` → `toolreplay` + `mentions` + `tools` + `llm`；`investigator` → `tools` + `llm` + `alert`；`mentions` → `device` + `alert` + `logquery`；`toolreplay` 仅依赖 `model/aiops.Message`。各包通过本地 interface（`MentionResolver`、`ToolInvoker`、`EventWriter`、`logQuerier`）暴露最小契约，便于单元测试注入 fake。
