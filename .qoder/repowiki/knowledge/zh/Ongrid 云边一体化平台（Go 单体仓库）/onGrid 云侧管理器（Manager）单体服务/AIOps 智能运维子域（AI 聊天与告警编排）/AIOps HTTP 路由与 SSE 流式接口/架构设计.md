本模块是 aiops 子域的 HTTP 边界层，仅依赖上层 biz/service/model/pkg 包，不反向依赖它们：
- 入口 `Handler` 通过 `Register(chi.Router)` 挂载 `/v1/chat/sessions`、`/v1/usage/today`、`/v1/aiops/*`、`/v1/agents*` 等路由；请求鉴权由上游中间件注入 `tenantctx`，handler 内用 `callerFromCtx` 提取 `svc.Caller`。
- 所有外部依赖（mentions 搜索、多 LLM 模型目录、chatruntime AgentRegistry、用户自定义 Agent CRUD、LLM 客户端）均以窄接口（`MentionSearcher`、`ModelCatalog`、`AgentLister`、`UserAgentManager`、`llm.Client`）注入，`NewHandler` 构造后通过 `SetXxx` 可选装配；nil 时对应端点优雅降级（返回空列表或 503），使老内核也能编译运行。
- 业务调用统一走 `AIOpsService` 接口（结构体匹配 `svc.Service`），DTO 在文件顶部集中声明，再由 `toSessionDTO` / `toMessageDTO` / `toPostMessageResp` 等转换函数映射到 model/biz 类型。
- 同步路径使用 `writeJSON`/`writeErr` 统一 JSON 响应与错误码映射（`errCode` → `not-found`/`unauthorized`/`forbidden`/`invalid`/`budget-exceeded`/`edge-offline`/`internal` 等）。
- 流式路径 `POST /v1/chat/sessions/{id}/messages/stream` 实现原生 SSE：先写 `: ok\n\n` 心跳，再按 `agent.Event` 类型映射为 `assistant/tool_start/tool_end/done/task_notification/approval_pending` 事件帧，不支持 Flush 时自动回退为阻塞 JSON。
- `query_translate.go` 独立承载 POST `/v1/aiops/query-translate`，内置 logql/traceql/promql 三种方言的系统提示模板，强制低温度 + 严格 JSON 输出，并带 120s 超时保护。
