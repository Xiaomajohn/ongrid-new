模块以 `Runtime` 为进程内入口，按职责拆分为以下子层：
- 数据模型层 (`types.go`)：定义 Skill / Agent / Pack / ToolDecl / Policy 等 YAML frontmatter 结构体，所有字段使用 snake_case 标签以兼容 claude-code 与 openclaw。
- 解析与注册层：`skill_parser.go` + `agent_parser.go` 将 SKILL.md / *.md 解析为内存对象；`skill_registry.go` / `agent_registry.go` 提供带 RWMutex 保护的只读快照式查询；`load_all.go` 统一遍历 SkillsRoot / AgentsRoot 并识别 `.claude-plugin/plugin.json` 与 `openclaw.plugin.json` 插件容器，递归加载。
- 提示组装层 (`system_prompt.go`)：`ComposeSystemPrompt` 按 basePrompt → agentProfile → activeSkills 顺序拼接，并在 coordinator 路径注入 `coordinatorToolRouting` 与 `buildAgentCatalog`。
- 执行内核 (`runtime.go`)：`Handle` 实现 PR-9 cutover 主路径——所有权校验→@mention 内联→用户消息先写盘→按 Persona 过滤 toolBag→构建 eino ReAct Graph→通过 `callbacks.NewDefaultHandlers` 挂接持久化/SSE/审计/预算回调→翻译 Output 为 Reply，同时把新事件名映射回 legacy SSE 帧以保持 SPA 兼容。
- 多 Agent 编排 (`worker.go`)：`SpawnWorker` / `SendToWorker` / `StopWorker` 维护 Runtime 内的 `map[string]*Worker`，每个 Worker 是独立 goroutine 驱动的一次 graph.Invoke，支持 background 模式并通过 `task_notification` SSE 帧回传状态；`filterToolsForAgentRole` 应用白名单/黑名单/控制工具隔离/viewer 降级策略。
- 依赖方向：本模块仅向上暴露 `Runtime` 与 `SkillRegistry`/`AgentRegistry` 接口，向下依赖 `graph`、`graph/callbacks`、`tools/basetool`、`biz/aiops/toolreplay` 和 `model/aiops`，不反向被 tools 包引用以避免循环。
