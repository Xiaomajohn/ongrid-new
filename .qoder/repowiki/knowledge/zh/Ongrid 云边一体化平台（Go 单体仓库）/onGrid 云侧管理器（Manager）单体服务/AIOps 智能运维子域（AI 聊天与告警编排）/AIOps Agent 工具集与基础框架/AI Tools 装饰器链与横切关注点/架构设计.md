本模块以 `basetool.BaseTool` 接口为唯一抽象，每个横切关注点实现为一个独立的 `*XxxTool` 结构体（audit.go、metric.go、ratelimit.go、timeout.go、tenant_bind.go、review_gate.go），对外暴露 `WithXxx(inner, deps) basetool.BaseTool` 构造器；所有装饰器仅依赖 `basetool` 包，不直接引用 biz repo 或 chatruntime，通过接口边界解耦：
- `AuditSink` / `MutatingProposalSink` 作为审计/提案写入的注入点，生产由 cmd/main.go 层绑定到具体 repo。
- `ReviewSpawner` 作为 reviewer worker 的运行时 seam，使 review_gate 可被单元测试用 fake 替换。
- `Limiter` 默认基于 `golang.org/x/time/rate` 按 (toolName, userID) 维度维护 token bucket，`NoopLimiter` 用于测试/禁用场景。
- `Deps` 聚合所有外部依赖并提供零值安全回退（DefaultTimeout=15s、DefaultRateLimit=10/min、DefaultReviewerTimeout=60s、prometheus.DefaultRegisterer）。
- `chain.go` 的 `Wrap(inner, deps)` 是唯一的装配入口，固定顺序为 `tenant_bind → review_gate → timeout → audit → ratelimit → metric`，并在注释中逐条论证每层相对位置的业务理由（如 review_gate 必须在 timeout 外以避免 LLM 评审被 15s 截断、必须在外层才能避免对拒绝路径产生虚假执行审计行等）。
- 指标收集器通过 `sync.Mutex + map[Registerer]*collectors` 懒注册并按 Registerer 复用，避免多 Wrap 调用在相同 registry 上重复注册导致 panic。
