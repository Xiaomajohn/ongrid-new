模块按三层拆分：
- `server/installjob`：HTTP 层，基于 chi.Router 暴露 `/v1/devices/{id}/install-edge`、`/v1/install-jobs/{id}`、`/v1/devices/{id}/install-jobs`、`/v1/edges/{id}/install-jobs`、`:cancel` 等 REST 端点；通过包内 `Usecase` 接口与 biz 解耦，当前由 main.go 注入 stub 以便 A4 后续替换。
- `biz/installjob`：领域内核。`model.go` 用 type alias 把 data 层的 `InstallJob`/`Status`/`EventKind` 重导出给上层，保持调用方无感知；`repo.go` 定义 `Repo` 接口并委托 `data/installjob.NewRepo`；`runner.go` 实现带容量上限的 goroutine 池（默认并发=2、队列深度=64），`worker.go` 驱动单 job 的状态机 `queued→running→(success|failed)`，并通过 `EdgeIssuer`/`Installer`/`EdgePresence` 三个窄接口接入外部依赖，全部可空以支持测试与部分 wiring。
- `data/installjob`：唯一持有 `*gorm.DB` 的数据层，包含 `InstallJob`/`InstallJobEvent` 两个 gorm 模型（软删除 + milli 级 delete_marker）、`GormRepo` 实现以及 `Migrate` 自动建表入口，被 `cmd/ongrid/main.go` 的迁移链注册。
依赖方向严格单向：`server → biz → data`，biz 不直接 import gorm，data 不反向引用 biz。
