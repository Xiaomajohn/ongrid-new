本模块是 Go 单包 `cmd/ongrid`，仅含一个可执行入口 `main.go`（~5300 行）及若干同包测试文件；它本身不包含业务逻辑，而是作为「装配器」把 `internal/iam` 与 `internal/manager` 两个有界上下文拼成完整服务。

启动阶段按严格顺序执行：
1) 读取 `config.Load()` → 用 `logger.WithService` 打日志 → 通过 `signal.NotifyContext` 绑定 SIGINT/SIGTERM 根上下文。
2) 初始化 OpenTelemetry tracing（默认 `tempo:4318`，可通过 `ONGRID_OTEL_ENDPOINT` 覆盖）。
3) `dbx.Open` 打开 MySQL/SQLite 后集中调用 `dbx.RunMigrations`，按依赖顺序注册 iam 与 manager 各 data store 的 `Migrate(db)`。
4) 依次构建 IAM（user/org/membership/casbin）、system_settings（LLM/Prom/Grafana/Loki/Tempo/WebSearch 首启种子）、LLM 多 provider 路由、edge/device/topology 等 usecase。
5) 构造 `frontierbound.Client`（长连接上游 frontier broker），注入 edge service 的 reverse-call 能力；若 `ONGRID_FRONTIER_DISABLED=true` 则使用 disabled stub。
6) 组装 SSH/SFTP/install-job 工作流（direct/tunnel 双通道由 `devicessh.Router` 选择）。
7) 注册所有 `managerserver*` handler 到 chi router，挂载 `/metrics`、`/api/*`、`/pages/*` 等路径。
8) 启动 `errgroup` 管理的 HTTP/Metrics 服务器，优雅关闭时 defer 关闭 tracing、DB、frontierbound。

模块内还包含面向 AIOps/Flow 的 shim 实现（`flowAgentRunner`、`flowLLMRunner`、`imSenderShim`、`filePageStore`、`flowToolCatalog`、`flowNotifierShim` 等），将上层 bizflow/aiops 接口桥接到 alert channel store、notify router、aiops tool registry 等运行时组件。测试文件 (`*_test.go`) 聚焦于入口层决策：kernel env 解析、coordinator 工具白名单与 base prompt 断言、LLM provider 默认选择策略。
