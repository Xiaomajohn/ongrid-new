模块按 HTTP server / biz 业务层 / data 存储三层切分，并拆成两条独立管线：
- `server/devicessh` + `biz/devicessh`：面向“设备直连或经 edge 隧道”的新路径，HTTP 层在 `/v1/devices/{id}/shell`（强制 tunnel）和 `/v1/devices/{id}/shell-direct`（强制 direct）两个 WS 端点之间分流；`fs.go` 暴露 `/v1/devices/{id}/fs/*` 的 SFTP REST 表面。biz 层的 `Router` 根据 `Purpose`（Shell/SFTP/InstallEdge）与 `RouteKind`（Auto/Direct/Tunnel）结合 `LinksLookup`+`EdgesGet` 决定走 `DirectDialer` 还是 `TunnelDialer`，并通过 `Session`/`Dialer` 接口屏蔽底层差异；`service.go` 把 `DeviceLoader`→`Router.Pick`→`Session.Shell` 串成 `OpenShell`。
- `server/webshell` + `biz/webshell`：保留旧的 edge-only WebSSH，HTTP 层通过 `Streamer.OpenStream` 打开 frontier 流到 edge，本地建 SSH client 并 PTY；`biz/webshell.Router` 维护 SessionID→Sink 的内存目录，支持 `CountByUser`/`CountByDevice` 并发限制、`Kill` 管理员终止以及 `Recorder` 审计写入。
- `data/webshell/store`：GORM-backed `Repo` 实现 `webshell.Recorder`，负责 `webshell_sessions` 表的 AutoMigrate、Insert/Close/List。
依赖方向严格单向：`server/*` → `biz/*` → `model/*`，`server/devicessh` 与 `biz/devicessh` 通过结构体平行的 `ShellOpts`/`ShellHandle` 避免 import cycle，由 main 组装时做适配转换。
