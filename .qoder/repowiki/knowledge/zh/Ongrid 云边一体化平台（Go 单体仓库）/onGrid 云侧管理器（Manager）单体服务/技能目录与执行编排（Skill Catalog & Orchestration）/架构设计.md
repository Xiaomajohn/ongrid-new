模块按 HTTP 层与应用服务层切分：
- `internal/manager/server/skill/http.go`：基于 chi 暴露 `/v1/skills`、`/v1/skills/{key}`、`/v1/skills/{key}/execute` 三个 REST 路由，仅负责参数解析、从 `tenantctx` 提取 Caller、统一错误编码，通过 `Service` 接口依赖应用层。
- `internal/manager/biz/skill/service.go`：核心编排层 `Service`，读取共享注册表 `internal/skill`（`skillcore.All`/`Get`），对每个 Execute 调用先经 `authorize(class, role)` 做 Class × Role 鉴权，再按 `ScopeHost`/`ScopeManager` 分支选择通过 `EdgeCaller.Call(tunnel.MethodExecuteSkill)` 下发到 Edge 或在进程内直接 `exec.Execute`；同时可选合并 chatruntime 注入的额外 SKILL.md 技能（`WithExtraSkills`）。`Caller`、`EdgeCaller`、`AuditSink` 均为窄接口，避免紧耦合 iam 与 DB。
- `internal/manager/biz/skill/audit.go`：默认实现 `GormAuditSink`，将每次 Execute 写入 `skill_executions` 表（`Migrate` 由 cmd/ongrid 主流程调用），失败降级为 warn 日志，不阻断业务。
依赖方向：server → biz → internal/skill + tunnel；biz 通过接口反向依赖外部（iam、DB、edge agent），HTTP 层只依赖 biz 的 Service 接口，便于测试注入 fake。
