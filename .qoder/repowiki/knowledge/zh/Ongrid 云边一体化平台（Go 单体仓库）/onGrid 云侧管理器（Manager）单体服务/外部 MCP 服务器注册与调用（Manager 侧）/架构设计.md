模块按三层划分，依赖方向自上而下：
- `server/mcp`：基于 chi 暴露 `/v1/mcp/servers` REST 路由（CRUD + `{id}/test`），所有接口均经 `requireAdmin` 校验 admin 角色；请求体经 `MaxBytesReader(64KB)` 限流后解码为 `serverInput`，再转为 `model.Server` 交给 Service。
- `biz/mcp`：定义 `Repo` 与 `SecretResolver` 两个窄接口，`Usecase` 组合二者完成业务编排——字段归一化/校验（`normalizeAndValidate`）、凭据解析（`SecretResolver.ResolveFields` → `expandHeaders` 替换 `{{field}}` 占位符生成 HTTP 头）、连接探测（`initialize → tools/list`，成功则写回 `tools_cache_json` 并置 status=`ok`，失败写 `last_error` 并置 `error`）以及受信任路径下的 `CallTool` 直接转发。
- `data/mcp/store`：GORM 实现的 `Repo`，仅做 CRUD 与状态写入（`SetStatus` / `SetToolsCache`），重复键错误统一包装为 `errs.ErrConflict`，不存在返回 `errs.ErrNotFound`；`migrate.go` 通过 `AutoMigrate(&model.Server{})` 建表。

对外边界：HTTP handler 只依赖 `Service` 接口（由 `bizmcp.Usecase` 满足），biz 层只依赖 `Repo` 与 `SecretResolver` 接口，避免反向耦合到上层 router 或下层 GORM。模型来自 `internal/manager/model/mcp`，MCP 客户端来自 `internal/pkg/mcpclient`，错误码来自 `internal/pkg/errs`。
