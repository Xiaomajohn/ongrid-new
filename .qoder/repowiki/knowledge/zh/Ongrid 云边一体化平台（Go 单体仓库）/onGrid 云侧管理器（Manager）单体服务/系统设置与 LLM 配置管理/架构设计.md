模块按三层划分：
- `server/setting`（HTTP 层）：基于 go-chi/v5 暴露 `/v1/system-settings` REST API，通过 `tenantctx` 从请求上下文提取用户角色，读接口对任意认证用户开放（敏感值始终掩码），写/删除/reveal 仅允许 admin；写入时自动根据 key 后缀 `_api_key/_secret/_token/_password` 标记敏感，并通过 `auditmw.SetAuditEvent` 记录审计事件。
- `biz/setting`（业务服务层）：`Service` 持有 `Repo` 接口与内存 `map[string]string` 缓存（`category|key` 为键，`sync.RWMutex` 保护），`Get` 命中则短路 DB，`Set/Delete` 后失效对应条目；`List` 返回 `SettingDTO` 并对敏感值执行“前4+***+后4”掩码策略；`SetIfAbsent` 用于启动时以环境变量种子值填充缺失行。同包内还包含面向消费方的解析器：`LLMSettingsResolver` 实现 `llm.ProvidersResolver`，将 `system_settings.llm.*` 行映射为多 Provider 配置，支持 env 默认值回退与 OpenAI legacy model 兼容；另有 `AgentSettingsResolver`、`ProbeSettingsResolver`、`PromAuthSettingsResolver`、`TelemetrySettingsResolver`、`WebSearchSettingsResolver` 等同构解析器。
- `data/setting/store`（持久化层）：GORM-backed `Repo`，使用 `ON CONFLICT (category, key)` upsert，唯一索引保证幂等；`migrate.go` 通过 `db.AutoMigrate(&model.Setting{})` 注册表结构，由 `cmd/ongrid` 的迁移编排统一调用。
依赖方向严格自上而下：server → biz → data，biz 通过接口解耦 repo，便于测试注入 mock。
