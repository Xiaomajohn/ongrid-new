本模块按职责拆分为两个层次：
- `internal/manager/biz/monitor`：仅包含 `service.go`，是“用户管理 Grafana 面板”的业务层，定义 `Repo`（持久化）和 `GrafanaSyncer`（单向镜像到 Grafana dashboard）两个窄接口，通过 `Service` 编排 CRUD 并在后台 goroutine 中异步触发同步，失败时落盘 `last_sync_error` 供 UI 展示。
- `internal/manager/server/{monitor,systemhealth,systemupgrade,prometheus,traces,logs}`：每个子目录对应一个 HTTP 端点组，统一采用 `Handler{svc ...} + Register(r chi.Router)` 模式，依赖注入对应的 service 或 Querier 接口；`monitor` 还额外维护了本地 biz 层的 `PanelService` 适配面，其余 handler 直接依赖 `internal/manager/service/*` 或 `internal/pkg/{promquery,tracequery,logquery}` 等下游包。

依赖方向严格自上而下：server → (biz) → service/data/pkg，handler 不直接访问 store，所有外部依赖均通过接口暴露以便测试替换。`prometheus` 同时提供 `RegisterProtected`（launch/query_range）和 `RegisterPublic`（auth ticket 校验）两套路由，通过 cookie `ongrid_prom_ticket` 实现滑动续期；`traces` 与 `logs` 作为只读代理，当底层 Querier 为 nil 时返回 503 而非 404，使 SPA 能优雅降级。
