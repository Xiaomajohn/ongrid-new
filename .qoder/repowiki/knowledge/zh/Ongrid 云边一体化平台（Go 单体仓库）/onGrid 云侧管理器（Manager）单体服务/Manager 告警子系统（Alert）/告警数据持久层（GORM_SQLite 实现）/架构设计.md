本包是 `internal/manager/biz/alert` 定义的 `biz.Repo` 接口的 GORM/SQLite 具体实现，依赖方向单向：store → biz（仅用于实现接口）、model/alert（实体定义）、pkg/errs（统一错误码），不反向被 biz 或 service 直接 import。

- 核心结构体 `Repo` 在 `repo.go` 中实现 `biz.Repo` 与内部 `Store` 接口，覆盖 incident/silence/rule/channel/delivery 五大实体的行级 CRUD、状态机更新（`UpdateIncidentStatus`、`UpdateSilenceStatus`、`UpdateDeliveryStatus` 均通过 `validateXxxStatus` 白名单校验）以及 firing-path 专用方法（`BumpIncidentFiring`、`ReopenIncident`、`MarkIncidentNotified`）。
- `investigation_repo.go` 单独提供 `InvestigationRepo`，实现 `biz/alert/investigator` 子包的查询器接口，与主 Repo 解耦。
- `provider.go` 暴露 `NewBizRepo(db)` 作为 wire 入口，将 `*gorm.DB` 转为 `biz.Repo`，供上层注入。
- `migrate.go` 集中管理 schema 演进：先调用 `db.AutoMigrate` 注册所有 model，再执行一系列幂等 backfill（kind 归一化、scope 拆分、edge_id→device_id 重命名列、metric_threshold→metric_raw 编译回写、legacy rule_key 重命名），并内嵌 `metricExprFor` 闭集映射避免循环依赖。
- `seed.go` + `seed_rules.go` 负责启动时从 `config.AlertConfig`/`NotificationConfig` 同步内置规则与通知渠道，使用 Upsert 语义保证幂等且保留管理员编辑。
- `types.go` 定义各实体的 Filter 结构体与 `Store` 接口，将 storage-specific filter 与 biz-facing filter 做一层薄包装（如 `ListChannels` 把 `biz.ChannelFilter` 转成 `ChannelFilter`）。
