本模块位于 `internal/manager/biz/alert`，围绕两个可插拔接口组织：
- `ChannelResolver`（`DBChannelResolver`）：每次调用通过 `channelLister.ListEnabledChannels` 拉取启用的 channel 行，先检查 incident 对应 rule 的 `NotifyChannelIDsJSON` 是否做了显式 pin；若命中则仅返回被 pin 且 enabled 的 channel，否则按 `MatchSeverityMin` + `MatchScopeTypes` 做全局过滤。无匹配时退回 `fallback` 列表构造的 synthetic channel（ID=0），供上层 `MaybeNotify` 继续投递。
- `Inhibitor`（`BuiltinInhibitor`）：在通知前查询是否存在更高优先级的活跃 incident（`edge_offline` 抑制同 host 的所有业务告警、`prom_ingest_fail` 抑制 `pipeline:scrape_down:*`），通过 `IncidentLookup.GetIncidentByDedupeKey` 读取并排除已 resolved 状态。
依赖方向单向指向 `model/alert`，对底层 repo 采用窄接口 `channelLister` / `IncidentLookup` 注入，避免测试耦合完整 biz.Repo；`RuleLookup` 以函数类型可选注入，nil 时回退到全局过滤行为。测试文件 `channel_sender_test.go` 还覆盖了 `BuildSenderFromChannel` 与 `channelHasDestination` 的通道构建/校验逻辑。
