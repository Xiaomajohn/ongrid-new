本模块位于 alert 子域的业务层，核心职责是「规则加载 → 编译 → 缓存 → 暴露」。
- 数据契约：repo.go 定义 Repo 接口（Incident/Event/Silence/Channel/Delivery/Rule 全量 CRUD）和 RuleSource 窄接口（仅 ListAllEnabledRules），CachedRulesProvider 依赖后者以解耦数据库实现；StaticRulesProvider 通过相同 RulesProvider 接口在测试与无 DB 部署中注入固定快照。
- 规则模型：rules.go 内聚八种已编译规则结构体（MetricRaw/MetricAnomaly/MetricForecast/MetricBurnRate/LogMatch/LogVolume/TraceLatency/TraceErrorRate），每种对应一个 `compileXxxRule` 函数，把 JSON ConditionsJSON 反序列化为 spec 并填充默认值、校验必填字段与枚举。
- 缓存策略：CachedRulesProvider 使用 atomic.Pointer[rulesSnapshot] 原子替换不可变 rulesSnapshot，Loop 以 time.Ticker 周期调用 Refresh；Refresh 内部对每条 row 按 model.NormalizeKind 分发到对应 compile 函数，单条编译失败仅 warn+continue，不阻断整个子系统。
- Scope 兜底：effectiveScope 对空 scope_type 按 kind 回填默认值，兼容历史行与测试 fixture。
- 依赖方向：本模块仅向上暴露 RulesProvider 给 evaluator，向下依赖 model.alert 与 repo.Repo，不直接访问 GORM/HTTP。
