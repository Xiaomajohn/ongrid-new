- 每个 handler 先调用 `callerFromRequest` 或 `requireAdmin` 提取 Caller 并短路返回 401/403，再解析 URL 参数与请求体，最后调用 service 并 `writeJSON` 响应。
- 错误一律包装为 `internal/pkg/errs` 中的哨兵错误，再由 `errCode` 统一映射到 HTTP 状态码，通过 `writeErr` 输出 `{error, code}` 结构体。
- 可选功能（investigation 读取/触发、runtime-info）通过 `WithXxx` 构造器注入 nil-safe 接口，nil 时返回语义明确的 200/503 响应体而非 panic。
- 变更类 handler 在成功返回前通过 `auditmw.SetAuditEvent` 记录 Action/ResourceType/ResourceID/Payload，保持审计与业务逻辑解耦。
- 测试采用单一 `fakeService` struct 同时实现三个 service 接口，用 lastXxx 字段断言传入参数，配合 `buildRouter` 注入 tenantctx 中间件。
