本模块是 alert 子系统的 HTTP 适配层，位于 `internal/manager/server/alert`，通过 `Handler.Register(chi.Router)` 集中注册三类资源的路由：
- `/v1/alerts/incidents[/{id}]` 及其子资源（events、investigation、ack/resolve/silence）——对应 `IncidentService` 接口；
- `/v1/notification-channels[/{id}]` 及 test ——对应 `ChannelService`；
- `/v1/alert-rules[/{id}]` 及 preview/enabled ——对应 `RuleService`。

依赖方向单向向下：handler → `svc.*` 服务接口 + `biz/alert/investigator`（可选）+ `model/alert`（仅 investigation 读路径），不直接访问数据层。可选能力通过 `WithInvestigations` / `WithInvestigationTrigger` / `WithRuntime` 注入，nil 时 GET 返回 `feature_disabled`、POST 返回 503，实现“按部署开关”的渐进式启用。

鉴权从 `tenantctx.Tenant` 上下文提取 `Caller{UserID,Role}`，写操作统一走 `requireAdmin` 校验 admin 角色；所有错误经 `errCode` 映射到标准 HTTP 码并通过 `writeErr` 以 `{error, code}` JSON 返回。审计事件通过 `auditmw.SetAuditEvent` 写入请求上下文，由上层中间件持久化。
