模块按三层切分：
- `server/marketplace`（HTTP 层）：基于 go-chi/v5 暴露 `/v1/marketplace/{install,upload,installed,registries}` 路由，通过 `Service` 接口依赖 biz 层，统一用 `mapErr` 把 `errs.Err*` 映射为 JSON `{error, code}` 响应。
- `biz/marketplace`（业务编排层）：核心是 `Usecase`，持有 `Repo`、`SkillRegistry`、`AgentRegistry` 三个外部依赖以及 `Config`（staging 目录、允许源白名单、RequireSignedSources、ECDSA 公钥钉住、DevMode 等）。`Install` 流程严格顺序化：权限检查 → 源白名单 → `fetchToStaging`（local/tarball/git 三种 SourceType）→ `chatruntime.DetectContainer` + `LoadPluginContainer` 解析 manifest → 路径逃逸与重复性校验 → rename/copyTree 落盘 → `VerifySignature`（signature.go）→ 可选的 RequireSignedSources 信任门 → 写入 DB → `reloadRegistries()` 热加载。
- `data/marketplace/store`（持久化层）：GORM-backed `Repo`，对 `installed_skills` 表做 Create/List/GetByPackID/GetByManifestSHA/DeleteSoft/SetBindings，软删除通过 `deleted_at IS NULL` 过滤；冲突检测通过匹配错误消息中的 `UNIQUE`/`Duplicate` 子串转成 `errs.ErrConflict`。

依赖方向：`server → biz → data/store`，biz 层通过接口（`Repo`、`SkillRegistry`、`AgentRegistry`、`Caller`）解耦外部注册表与数据库；`signature.go` 使用 ECDSA P-256 + SHA-256 对 pack 中除 `signature.json` 外的所有 `.md/.json` 文件拼接计算摘要，支持 `pub_key` 钉住；`targz.go` 负责 tar.gz 解压，`git_shorthand_test.go` 对应的 `expandShorthandGitURL` 把 `owner/repo` 简写展开为 GitHub HTTPS URL。
