模块按三层划分：
- `server/report`：基于 chi 的 HTTP 层，分 `http.go`（认证、RBAC `viewer`/writer 路由注册、DTO 转换）和 `task.go`（HLD-022 Phase 2 的统一任务表面，将 recurring schedule 与 oneoff task 合并到 `/v1/tasks`）。所有写操作经 `requireWriter` 中间件拦截，读共享报告通过 `RegisterPublic` 挂载在 `/r/{token}`。
- `biz/report`：领域用例层，核心是 `Usecase`（CRUD schedule、`FireSchedule` 去重+重排、`GenerateNow` 手动触发），依赖注入 `Repo` 接口（由 data 层实现）、`Generator` 接口（LLM 内容生成工作器，PR-1 默认 `nopGenerator`，`NewUnavailableGenerator` 用于启动期未配置 provider 时返回 `ErrNotWiredYet`）、`IDGen` 与可选 `ReadRepo`；`cron.go` 仅用 robfig/cron 解析 spec 并计算 `CronNext`，`scheduler.go` 自建 `time.Ticker` 每分钟扫描 `DueSchedules` 并调用 `Usecase.FireSchedule`，对坏 tz/spec 自动禁用 schedule；`period.go`/`content.go`/`facts.go`/`delivery.go`/`generator.go`/`task.go` 分别承载周期计算、标题/内容模板、事实收集、投递、异步生成编排与 oneoff task 逻辑。
- `data/report/store`：GORM 持久化，`repo.go` 实现 `bizreport.Repo`，并通过 `isDuplicateKey` 把 MySQL ER_DUP_ENTRY / SQLite UNIQUE constraint failed 翻译为 `errs.ErrConflict`，供 Usecase 做幂等去重；`migrate.go` 负责建表，`read.go`/`facts.go`/`task.go` 补充查询与 oneoff task 读写。
依赖方向严格单向：server → biz → data/store，模型统一来自 `internal/manager/model/report`。
