模块按「本地开发」和「生产安装」两条路径组织：
- `deploy/docker-compose.yml` 是本地开发入口，在 `ongrid_net` bridge 上编排 mysql、ongrid（Dockerfile.ongrid）、nginx/web（Dockerfile.web）、frontier（singchia/frontier:1.2.5）、prometheus、loki、tempo、qdrant、grafana、searxng 等容器，通过 `depends_on` + healthcheck 保证启动顺序。
- `deploy/install/` 是随发布包交付的生产级资源：`install.sh` / `upgrade.sh` / `uninstall.sh` 负责在宿主机创建 `/opt/ongrid/{ongrid,ongrid-web,data,logs}` 四子目录布局、生成自签 TLS 证书、加载预构建镜像、渲染 `.env`、以 `docker compose --env-file .env up -d` 拉起服务；`systemd/` 下提供同一套资源的 systemd unit 替代形态（`--mode=systemd`）；`edge/` 下放 `install-edge.sh` 用于受管主机一键安装 ongrid-edge agent。
- `deploy/Dockerfile.*` 定义多阶段镜像：`Dockerfile.ongrid`（CGO_ENABLED=1，debian:bookworm-slim 运行态，内嵌 ONNX Runtime 共享库供 fastembed-go 使用）、`Dockerfile.ongrid-edge`（纯 Go 静态编译，distroless）、`Dockerfile.web`（前端 SPA + nginx）。`Dockerfile.frontier` 仅用于打包 frontier 二进制。
- `resource/auditbeat/` 存放审计代理的 linux-amd64/arm64 裸二进制及对应 tar.gz 归档，作为独立可分发组件。
依赖方向单向：install 脚本只读 deploy 下的 compose/Dockerfile/配置文件，不反向引用源码；compose 通过 bind-mount 把 `./edge`、`../.cache/*` 暴露给 ongrid 容器，实现升级包与宿主缓存的桥接。
