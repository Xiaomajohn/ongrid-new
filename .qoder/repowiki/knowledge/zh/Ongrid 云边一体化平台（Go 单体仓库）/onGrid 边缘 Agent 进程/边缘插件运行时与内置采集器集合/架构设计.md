本模块由三层组成：
- 核心框架（plugin.go / supervisor.go / subprocess.go）：定义 `Plugin` 接口（Name/Configure/Start/Stop/HealthSnapshot）、`PluginConfig` 与 `PluginHealth` 契约，并通过 `SubprocessPlugin` 把外部二进制（promtail、otelcol-contrib、auditbeat）封装成与 in-process goroutine 一致的子进程；`Supervisor` 按 60s tick + reload 信号驱动 reconcile 循环，对每个已注册插件做 diff 后调用 Configure/Start/Stop，并聚合 `HealthSnapshot` 上报。
- 配置拉取层（config_env.go / config_tunnel.go）：实现 `ConfigFetcher` 接口的两种来源——本地环境变量回退与 manager 隧道推送，使 Supervisor 无需感知配置来源。
- 具体插件目录（metrics/hostmetrics/procmetrics/databasemetrics/custommetrics → built_in_metrics_scrapers；logs/traces/audit → output_render_plugins）：各自实现同一 `Plugin` 接口并按 OTel 信号名（"metrics"/"logs"/"traces"/"profiles"）注册到 Supervisor，被统一调度。

跨子模块的统一约束：所有插件通过 `Name()` 返回的字符串作为 registry key 和 manager 侧配置行键；`Spec` 字段承载插件特定 JSON spec，由各自 render/spec 文件解析；子进程插件一律走 `subprocess.go` 的 `SubprocessPlugin` 基类，共享 SIGTERM+SIGHUP 重启策略与 PID 上报。
