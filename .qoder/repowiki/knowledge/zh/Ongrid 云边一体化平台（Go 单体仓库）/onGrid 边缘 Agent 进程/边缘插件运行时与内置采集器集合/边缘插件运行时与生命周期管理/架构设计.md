模块以 `Plugin` 接口（`Name/Configure/Start/Stop/HealthSnapshot`）作为统一抽象，Supervisor 通过 `ConfigFetcher` 获取每周期快照并 diff 后对每个已注册插件执行 Configure→(可选 Stop)→Start 的幂等编排。

- 进程内 vs 进程外：`SubprocessPlugin` 是通用基类，封装二进制路径、工作目录、配置文件渲染函数 (`configRender`)、CLI 参数构建函数 (`args`)、SIGTERM 优雅退出、日志文件输出、指数退避重启（1s→5min 上限）和 PID/StartedAt 健康字段；具体能力（logs/promtail、traces/otelcol 等）只需实现渲染与参数构造即可复用该基类。
- 配置来源分层：`EnvConfigFetcher` 从 `ONGRID_EDGE_PLUGIN_<NAME>_...` 环境变量读取（开发/冷启动），`TunnelConfigFetcher` 通过 `tunnel.Client.Call(tunnel.MethodGetPluginConfigs)` 从 manager 拉取，并在 RPC 失败时回退到 Env 快照，二者均实现 `ConfigFetcher` 接口，在 main.go 中组合注入。
- 状态机：`PluginState` 仅 four-state（stopped/starting/running/crashed），`PluginHealth` 携带 `RestartCount`（单调递增，仅在 manager 推送新配置重新启用时重置）、`LastError`（成功启动后清空）和可选的 `Targets` 列表，供心跳上报。
- 并发模型：Supervisor 单 goroutine 持有 `sync.Mutex` 保护 plugins/current/running 三张表，`reconcile` 先拷贝快照再逐个调用插件方法；`SubprocessPlugin.runLoop` 独立 goroutine 负责子进程生命周期，通过 `wantRunning` + `cancelRun` + `stoppedCh` 协调停止。
- 依赖方向：supervisor → plugin interface → (subprocess | in-process impl)；config fetcher 反向依赖 supervisor 注册的已知插件名集合以过滤未知条目，避免循环。
