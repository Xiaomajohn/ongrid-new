三个独立子包 `databasemetrics`、`hostmetrics`、`procmetrics` 均实现 `plugins.Plugin` 接口，由上层 edgeagent 插件管理器统一注册和调度。

- `hostmetrics` / `procmetrics`：轻量包装器，直接委托 `plugins.NewSubprocess(SubprocessOpts)` 启动 `node_exporter` / `process_exporter` 二进制；区别在于 hostmetrics 使用 CLI 参数驱动（ConfigRender=nil），procmetrics 用 Go template + yaml.v3 渲染 YAML 配置文件再传入 `-config.path`。
- `databasemetrics`：更重，内部维护 `map[string]sourceSpec` 多源生命周期，每个 source 在独立 goroutine 中拉起对应 exporter 子进程，并通过 `metricscommon.Scrape` 拉取 `/metrics`，再用 `Pusher.Call(tunnel.MethodPushPromSamples, ...)` 经 tunnel 推送给 manager；凭据通过 edge-local 受管 secret 文件（0600 权限校验）注入环境变量，而非写入磁盘配置。
- 健康状态：所有插件都维护 `plugins.PluginHealth` 快照，`databasemetrics` 额外按 source 维度维护 `TargetHealth` 列表，并在 panic 时 recover 记录堆栈。
- 依赖方向：本模块只依赖 `internal/edgeagent/plugins`（插件框架）、`internal/edgeagent/plugins/metricscommon`（通用 scrape/up 样本）、`internal/pkg/tunnel`（RPC push），不反向依赖上层 edgeagent。
