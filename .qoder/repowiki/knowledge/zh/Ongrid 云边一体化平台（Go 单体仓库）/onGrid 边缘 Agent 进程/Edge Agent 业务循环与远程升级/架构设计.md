模块以 `Agent` 为单一入口，通过 `NewAgent(client, collector, cfg, log)` 装配依赖，由 `Run(ctx)` 驱动三个并发 goroutine（heartbeatLoop、metricsLoop、upgrade-watch）并用 `errgroup.WithContext` 统一生命周期。

- 分层边界：对外仅暴露 `Collector` 接口（定义在 `agent.go`），具体采集器位于子包 `collector/`（cpu/mem/net 占位实现，Phase 1 返回零值），使 agent 与 gopsutil / HTTP scrape 后端解耦；RPC 层通过 `tunnel.Client` 抽象，避免 biz 直接依赖服务实现。
- 事件总线：所有 cloud→edge 调用经 `registerHandlers()` 注册到 `tunnel.Client.RegisterHandler`，包括 legacy 的 `get_host_load`/`get_process_list`、统一的 `execute_skill`（转发至 `skilldispatch.Dispatch`）、以及条件启用的 `agent_upgrade`/`fetch_package`/`apply_package`（仅在配置了 `UpgradeStageDir` 时注册）。
- 健康与恢复：`OnReconnect` 回调在隧道重建后重发 `register_edge`；连续心跳失败超过 `tunnelStuckThreshold=5` 次则返回 `errTunnelStuck` 让 systemd 重启进程；成功 register 后写入 `<stage>/healthy_marker` 供启动脚本做回滚判定。
- 远程升级：`upgrade.go` 实现下载→流式 SHA256 校验→原子 rename 到 `pending` + 写入 `pending.sha256`，并通过带缓冲 1 的 `upgradeRequested` channel 通知 Run() 退出，由 systemd ExecStartPre 完成 swap；`upgrade_package.go` 处理 bundle 拉取与分步 apply。
- 辅助：`json.go` 提供泛型 `jsonEncode[T]` 把 handler 返回值与错误打包成 JSON，保持每个 handler 一行编码；`noopCollector` 兼容旧 `New()` 构造路径。
